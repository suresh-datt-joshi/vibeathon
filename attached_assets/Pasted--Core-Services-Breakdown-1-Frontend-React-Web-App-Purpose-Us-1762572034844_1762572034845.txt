## ⚙️ **Core Services Breakdown**

### 1. **Frontend (React Web App)**

* **Purpose:** User interface for managing projects, requirements, architecture, and tasks.
* **Responsibilities:**

  * Project creation, requirement input
  * View generated architecture and tasks (Kanban board)
  * Edit and approve AI-generated tasks/specs
  * Display reports and progress
* **Interaction:**

  * Calls backend REST APIs (`/api/projects`, `/api/tasks`, etc.)
  * Uses WebSockets for live updates (task status, AI job completion)

---

### 2. **Backend (Node.js + Express)** → *acts as API Gateway*

* **Purpose:** Orchestrates requests between frontend, FastAPI AI service, and the database.
* **Responsibilities:**

  * Handles authentication (JWT)
  * CRUD for projects, tasks, users, workspaces
  * Queues AI job requests to FastAPI
  * Integrates with external tools (GitHub, Jira, Slack)
  * Manages job results from AI service
* **Interaction:**

  * Communicates with **FastAPI** via HTTP or gRPC for AI tasks
  * Stores/retrieves all persistent data in **MongoDB**
  * Publishes/consumes messages from **Redis Queue**

---

### 3. **AI Service (FastAPI - Python)**

* **Purpose:** The “brains” of the platform — performs all LLM-based analysis and generation.
* **Responsibilities:**

  * Requirement analysis & system decomposition
  * Architecture generation (modules, APIs, database schema)
  * Task generation (epics, stories, subtasks)
  * Developer prompt & spec generation
  * Replanning (update tasks if requirements change)
  * Uses OpenAI or local models (LLM)
* **Endpoints Example:**

  * `POST /v1/decompose` → Generate architecture
  * `POST /v1/generate_tasks` → Create Jira-like tasks
  * `POST /v1/generate_prompts` → Produce dev prompts/specs
  * `GET /v1/job_status/{id}` → Get async job result
* **Interaction:**

  * Called by **Node backend** via REST
  * Returns structured JSON responses
  * Can use **Redis** to publish job status updates

---

### 4. **MongoDB (Primary Database)**

* **Purpose:** Persistent storage for all project and task data.
* **Collections:**

  * `users`, `projects`, `tasks`, `services`, `prompts`, `specSheets`, `integrations`
* **Interaction:**

  * Accessed directly by **Node backend**
  * AI results are stored after being returned to backend

---

### 5. **Redis (Job Queue / Cache Layer)**

* **Purpose:** Queue system for async tasks (AI job management).
* **Responsibilities:**

  * Manage long-running AI jobs (generate plan, decompose, etc.)
  * Cache recent responses to reduce LLM calls
* **Interaction:**

  * **Node backend** → Publishes job
  * **FastAPI** → Subscribes, processes, pushes results

---

### 6. **External Integrations**

| Integration | Purpose                       | Interaction               |
| ----------- | ----------------------------- | ------------------------- |
| **GitHub**  | Link repos, PRs to tasks      | Node backend → GitHub API |
| **Jira**    | Sync tasks with Jira tickets  | Node backend → Jira API   |
| **Slack**   | Notifications, slash commands | Node backend → Slack API  |

## 🔁 **Service Interaction Flow**

### 🧠 AI Workflow (Example: Generate Tasks from Requirements)

```
1️⃣ User enters project requirement → Web App
2️⃣ Frontend calls Node API: POST /api/ai/decompose
3️⃣ Node → sends request to FastAPI (POST /v1/decompose)
4️⃣ FastAPI → runs LLM → returns architecture JSON
5️⃣ Node saves result to MongoDB → returns to frontend
6️⃣ Frontend displays architecture diagram
7️⃣ User clicks "Generate Tasks"
8️⃣ Node → FastAPI (POST /v1/generate_tasks)
9️⃣ FastAPI → LLM → returns tasks
🔟 Node stores tasks → updates WebSocket to UI
```

### 💾 Data Flow Overview

| Layer      | Data Type              | Example                                         |
| ---------- | ---------------------- | ----------------------------------------------- |
| Frontend   | JSON payloads via REST | `{projectId, requirements: "Build a food app"}` |
| Backend    | MongoDB documents      | Project, Tasks, Prompts                         |
| AI Service | Structured JSON        | `{"modules": [...], "tasks": [...]}`            |
| Queue      | Async Jobs             | `jobId: 9812, type: "generate_tasks"`           |

---

### 📡 Communication Summary

| From    | To            | Protocol           | Purpose                     |
| ------- | ------------- | ------------------ | --------------------------- |
| Web App | Node.js       | HTTPS/REST         | UI actions (CRUD, AI calls) |
| Node.js | FastAPI       | HTTPS/REST or gRPC | AI processing requests      |
| Node.js | MongoDB       | Driver (Mongoose)  | Data persistence            |
| Node.js | Redis         | Pub/Sub            | Async job queue             |
| FastAPI | Redis         | Pub/Sub            | Job completion signaling    |
| Node.js | Web App       | WebSocket          | Real-time updates           |
| Node.js | External APIs | HTTPS              | Integration syncs           |
